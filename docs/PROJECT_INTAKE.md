# Project evidence pack

Send ONE project at a time. Start with work where you can explain your individual contribution and show the strongest evidence. Raw notes are better than polished but vague claims.

Upload the ZIP in this conversation. Do not upload confidential evidence, credentials or client data to this public GitHub repository.

## Suggested folder

```text
project-name/
  brief.md
  screenshots/
    01-main-experience.png
    02-key-workflow.png
    03-admin-or-mobile.png
  architecture/
    diagram.png
  demo/          # optional walkthrough
  evidence/      # REDACTED, approved evidence only
```

Screenshots: original PNG, WebP or high-quality JPEG, not images pasted into a CV or collage. For a web product, approximately 1600px wide or greater is useful. For mobile, share original device captures. Include the screen name and what it proves. A short walkthrough is optional; screenshots plus notes are the primary material.

## Minimum useful submission

Project name + problem + your role + your contribution + stack + three screenshots + available links. Send this first; the rest can be developed through focused questions.

## Publishing checklist

- Client permission recorded; anonymise when required.
- Secrets and personal/customer data removed.
- Role and dates accurate; team achievements distinguished from individual work.
- Screenshots show the actual product, not a mock-up presented as production.
- Metrics have a source, period and measurement definition.
- Links checked and public; no placeholder buttons.
- Architecture diagrams distinguish real implementation from proposed improvements.

This pack becomes one consistent source for the portfolio case study, resume achievement bullets and LinkedIn Experience/Featured content. Keep private evidence in the conversation or an approved private workspace, never in the public site source.
