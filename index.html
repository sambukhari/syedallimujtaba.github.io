Support Chat Core

Conversations, connected.

A Laravel support-chat core connecting a visitor widget with a human support team through Server-Sent Events.

LaravelPHPSSE
Explore repository ↗
Under the hood +

The problem

A reusable support-chat foundation needs to coordinate visitor messages, human operators and conversation state.

Inside the implementation

The public source includes conversation and message models, visitor and operator endpoints, and an SSE stream that notifies clients when new events exist.

An engineering detail

The event stream emits event metadata; clients retrieve the message content separately. The inspected implementation uses short-lived streaming requests.

Protocol fields from the source
Content-Type: text/event-stream
conversation_uuid  /  event_id  /  type

The README describes this as a non-AI core. Source inspection is not a deployment, scalability or security certification.

02 / Developer tooling
Reported.
Exception→Reportable hook→Email alert
Documented command · not a product screenshot

Laravel Exception Alert

When things break, know.

A configurable Laravel package that sends exception details by email without replacing an application’s report or render methods.

LaravelPHPEmail
Explore repository ↗
Under the hood +

The problem

Application errors need a direct route to the developer without a disruptive integration.

Inside the implementation

A trait registers a Laravel reportable callback, checks configuration, sends a Mailable and catches delivery failures. The package documents install, test and uninstall commands.

An engineering detail

The inspected trait sends synchronously by default. The alert is configurable by exception status, with failures logged rather than allowed to escape the mail block.

Commands from the package README
php artisan exception-alert:install
php artisan exception-alert:test

No installation counts, production adoption or response-time improvements are claimed. Framework compatibility should be checked for each consuming application.

Source-derived structure · not a product screenshot

Multi-company Chat Platform

One product. Clear boundaries.

A Laravel application with company sites, human-agent workspaces and company-scoped conversation handling.

LaravelPHPCompany scoping
Explore repository ↗
Under the hood +

The problem

A support platform needs separate workspaces for administrators, companies and support operators.

Inside the implementation

Routes define these workspaces and a widget script endpoint. The inspected chat controller scopes queries to the operator’s company and checks company ownership before conversation actions.

An engineering detail

Conversation join, reply, close and leave are explicit actions; replies require assignment to the current human operator.

Query excerpt from ChatController.php
Conversation::where('company_id', $agent->company_id)

The README is framework boilerplate. These descriptions are limited to inspected routes and controller code. AI behavior, billing, deployment and commercial usage are not verified.
